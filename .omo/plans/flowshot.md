## TL;DR (For humans)

<!-- Plain English for a non-engineer: NO file paths, NO todo numbers, NO wave/agent/tool names. -->

**What you'll get:** FlowShot - a brand-new screenshot tool for Linux that does everything Flameshot does (region/fullscreen/per-monitor capture, timer, the complete annotation set: pencil, line, arrow, rectangle, ellipse, highlighter, text with proper input-method support, secure pixelate, blur, invert, numbered step-bubbles, magnifier with pixel grid, screen color-picker, crop, undo/redo, layering - plus copy/save with filename patterns, pin-to-screen, Imgur upload, tray icon, background daemon, global hotkeys, and a clean, sane command line of our own design - capability-compatible with Flameshot, deliberately NOT interface-compatible, per user direction), but with everything Flameshot left broken on modern Linux desktops actually working: mouse-position-aware capture on Hyprland/sway/KDE, selection spanning across all monitors again, clipboard that reliably survives, correct output on mixed-DPI screens, pins that don't distort on fractional scaling, a visible crosshair, a hide-cursor option, built-in global shortcuts, and never a forced legacy-X11 fallback. Delivered with AUR/Nix/Flatpak packaging and honest per-desktop documentation.

**Why this approach:** Two load-bearing decisions: (1) FlowShot talks to each desktop's NATIVE screen-capture protocol directly - a negotiated ladder starting with the new standardized capture protocol (which also legally provides the mouse position Flameshot claims is impossible) and falling back per-desktop - instead of one lowest-common-denominator mediator; that is what buys back speed, cursor awareness, and pixel-perfect scaling. (2) One portable Rust rendering stack (the family modern tools like Zed are built with) paints every pixel of the UI through a shared design-token system - so it can genuinely look high-end, and a future Windows/macOS port swaps only the capture layer, never the app.

**What it will NOT do:** No screen recording, OCR, or scroll capture. No Windows/macOS/X11 code yet - architecture gates keep those doors open and a roadmap documents each phase. No GNOME shell extension: on GNOME a couple of conveniences (pre-selection at the cursor) honestly degrade and are documented. No shelling out to external screenshot tools, no telemetry, no update checker, no importing Flameshot's old config files.
